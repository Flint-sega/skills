# foreman

**«Прораб»: расскажи словами, что нужно построить — получи готовый проект.**

Прораб — skill для AI-агентов (Claude Code, Cursor, Codex, ZCode и другие): он берёт
вашу идею, задаёт вопросы ровно там, где в ней есть развилки, а дальше сам пишет
спецификацию, продумывает то, о чём вы не думали, режет работу на таски и собирает
проект целиком. Вам не нужно читать спецификацию, оценивать таски или разбираться
в коде. Название — про главное правило: прораб руководит бригадой субагентов и сам
кирпичи не кладёт — клавиатура оркестратора не трогает код проекта.

Это форк [autopilot](https://github.com/nick-vels/skills) от Nick Vels — переработанный
на его ядре версии 2.0 и разошедшийся осознанно. Что изменилось — в разделе
[«Отличия от autopilot»](#отличия-от-autopilot).

## Установка

### Через skills CLI

```bash
npx skills add Flint-sega/skills --skill foreman -g -y -a claude-code   # или cursor | codex
```

### Вручную (ZCode и любой другой агент)

Навык самодостаточен — это папка с правилами. Клонируйте и подключите симлинком
в каталог скиллов вашего агента:

```bash
git clone https://github.com/Flint-sega/skills.git ~/skills-foreman
mkdir -p ~/.agents/skills ~/.zcode/skills
ln -s ~/skills-foreman/skills/foreman ~/.agents/skills/foreman
ln -s ~/.agents/skills/foreman ~/.zcode/skills/foreman     # для ZCode
```

Проверка: попросите агента `/foreman` — он представится и назовёт режим.

## Пять видов работы

Один навык, пять глаголов. Слово перед задачей выбирает вид работы;
без слова — обычная сборка.

| Глагол | Пользователю | Что делает |
|---|---|---|
| `/foreman build` *(по умолчанию)* | Сборка | идея → вопросы на развилках → спецификация → таски → собранный и проверенный проект |
| `/foreman program` | Программа | длинный план по файлу (`STATE.md`): задачи выполняются по одной, каждая — коммит, файл сам ведёт учёт |
| `/foreman verify` | Проверка | слепая приёмка готового: субагент, не видевший спецификацию, запускает проект и сверяет с вашими словами |
| `/foreman incident` | Инцидент | сломалось: остановить кровь → снять улики → найти механизм → починить обычным тикетом с красным тестом → записать |
| `/foreman docs` | Документация | README и память проекта переписываются **по коду**, не по плану; каждая документируемая команда исполняется |

## Ручки сборки

После `/foreman` — голые слова, без дефисов; нераспознанное считается задачей.

| Ручка | Значения | Что меняет |
|---|---|---|
| режим | `full` · `semi` *(умолчание)* · `interview` · `manual` | сколько спрашивают о продукте и согласуют процесс |
| глубина | `strict` · обычная *(умолчание)* · `deep` | сколько продумывается сверх сказанного |
| запуск | `serial` | субагенты строго по одному — если параллельные сессии у вашего провайдера падают |

Пример: `/foreman full deep интернет-магазин керамики` — полный автомат с максимальной
проработкой. Русские фразы-триггеры работают во всех режимах: «полный автомат»,
«погриль меня», «ручной режим», «строго по брифу», «проработай глубоко», «вылижи»,
«по одному».

## Дашборд

В начале работы агент сам открывает дашборд — один HTML-файл: этапы, прогресс,
сколько осталось, что делается прямо сейчас. Обновляется сам каждые 10 секунд,
интернет не нужен, работает и просто двойным кликом. Набор этапов — данные из
состояния: дашборд программы показывает этапы программы, а не сборки.

## Что под капотом

- **Требования не исчезают молча.** Ваши слова становятся нумерованным манифестом;
  снять требование можете только вы, цитатой. Четыре гейта (G1–G4) проверяют
  соответствие на каждом шаге, включая слепую приёмку в конце — из чистого клона
  репозитория, ловит незаписанные зависимости.
- **Учёт ведёт `ap.py`** — одна команда на событие: время ставит скрипт, статусы
  требований и гейт G3 считает он, снимок состояния сам попадает в дашборд.
  Ручных правок `state.js` нет по определению.
- **Ревью там, где оно дорого.** До коммита проверяются фундамент и рискованные
  таски (вход, деньги, удаление, секреты); в конце — одно ревью всей ветки.
  На ремонт уходит только помеченное блокирующим — дословно.
- **Конвенции проекта — обязывающий вход.** `AGENTS.md`/`CLAUDE.md` проекта читается
  до начала работы и строится по нему; свой файл не изменяется без согласия.
  В существующем коде спеке предшествуют заметки с точными именами сущностей,
  в конце крупных сборок появляется словарь `CONTEXT.md`.
- **Секреты не запрашиваются и не записываются.** Вставляете ключи сами в `.env`;
  брифы проходят редакционный фильтр до записи.
- **Необратимое — всегда вопрос.** Деплой, оплата, рассылка, удаление — согласование
  в любом режиме; исполнители и приёмка ничего наружу не делают — ни `git push`,
  ни настоящих писем и оплат.

## Отличия от autopilot

Ядро — [autopilot 2.0](https://github.com/nick-vels/skills) (MIT, © Nick Vels):
`ap.py`, модель ревью, приёмка из клона, словарь `CONTEXT.md`, Windows-фиксы.
Слои foreman поверх:

1. **Глаголы** `program` / `verify` / `incident` / `docs` — длинные программы,
   слепая приёмка по требованию, разбор инцидентов, документация по коду.
2. **Конвенции проекта** — `AGENTS.md`/`CLAUDE.md` ингестируется как обязывающие
   правила прогона (`conventionsFile`), а не только сохраняется.
3. **Харнесс-агностичность на деле**: корни поиска `~/.zcode/skills`, генерик-открытие
   панели, rich-триггеры в description (навык срабатывает и на фразу, не только
   на `/foreman`), `--logs-dir` в measure-run.
4. **Диал `serial`** — последовательный запуск субагентов для флапающих провайдеров.
5. **Набор стадий дашборда — данные из state**: своя дорожка этапов для программы,
   веса; `ap.py` ранжирует, закрывает и аудирует по порядку из state.
6. **CI**: тесты `ap.py`, сканер секретов (формы — зеркало редакционного фильтра
   навыка), синтаксис JS шаблона.

Рантайм совместим с живыми прогонами autopilot: каталог `.autopilot/`, маркеры
в памяти проекта и localStorage-ключи дашборда не переименованы — прерванная
сборка autopilot резюмится прорабом.

## Структура

```
skills/foreman/
├── SKILL.md            оркестратор: глаголы, ручки, порядок фаз, гейты
├── phases/             правила каждой фазы — читаются в момент фазы, не раньше
├── prompts/            контракты субагентов (executor, review) — передаются путём
└── tools/ap.py         учёт прогона: одна команда на событие
```
